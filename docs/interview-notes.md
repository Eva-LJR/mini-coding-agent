# 面试讲解提纲

## 一句话架构

模型负责决策，本地工具负责执行，Agent 循环负责把两者连接起来并维护上下文。

## 为什么不用普通聊天接口直接生成代码

普通回复只能产生文字，无法证明文件真的被修改、测试真的被运行。tool calling 让模型产生带工具名和 JSON 参数的结构化请求，本地程序执行后再返回真实结果。

## 为什么要保存对话历史

模型下一轮需要看到之前读到的代码、测试错误和修改结果。缺少工具结果时，模型只能猜测当前状态。

## 终止条件

- 模型不再调用工具并返回最终文本；
- 达到最大模型调用轮数；
- 用户中止；
- 出现无法恢复的客户端异常。

## 工具错误如何处理

路径不存在、参数错误和命令失败通常不会直接结束 Agent，而是转换为工具结果交还模型。模型可以据此修改路径、命令或代码。API 连接失败等上层异常则由命令行入口统一报告。

## 安全设计

- 所有文件路径解析后必须位于工作区根目录；
- `.env`、私钥和常见凭据文件对文件工具不可见且不可读写；
- 命令默认逐次询问用户；
- 子进程不继承名称中含常见敏感词的环境变量；
- 命令有超时，输出有长度限制；
- 文件大小和 Agent 最大轮数有限制。

## 必须主动承认的局限

命令行工具仍不是完整沙箱，因为通过终端执行的程序理论上能访问工作区之外的资源。当前版本适合可信的本地演示；更严格的生产方案应把工具放入低权限容器，并加入系统调用、网络和资源限制。

## 为什么选择 Chat Completions 接口

题目允许模型厂商的 API 客户端和模型原生 tool calling。Chat Completions 形式被多种 OpenAI-compatible 服务支持，便于更换模型，同时核心 Agent 逻辑仍完全由本项目实现。
